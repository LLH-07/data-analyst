## Dataset

The dataset contains approximately:

- 20,000 transaction records
- 16 attributes
- September 2023 to September 2024

Fields include customer demographics, product type, SKU, order status, payment method, price, quantity, purchase date, shipping type, rating and add-on purchases.

The dataset is **synthetic**.

The original notebook states that it was generated by Cameron Seamons and does not represent real customer transactions.

Therefore, conclusions from this project should be interpreted as an analytical exercise rather than evidence about an actual electronics business.

## Known limitations

Looking back at the project now, I can identify several weaknesses.

### 1. Synthetic data

The data does not represent real business transactions.

This limits how strongly the findings can be generalized.

### 2. Business questions are relatively basic

Most analyses are based on counts, grouping and visualization.

The project does not yet include more useful business metrics such as:

- revenue growth
- average order value
- cancellation rate
- repeat purchase rate
- month-over-month performance
- customer value

### 3. Manual age segmentation

Customer age groups were created manually.

Different age boundaries could produce different results, and the original notebook does not provide a business justification for those boundaries.

### 4. pandas chained-assignment risk

The add-on analysis creates a subset and then modifies a column in that subset.

This pattern can lead to `SettingWithCopyWarning` and should be rewritten using an explicit `.copy()` or `.loc[]`.

### 5. Descriptive results were sometimes turned into broad recommendations

Counts and distributions can identify patterns but do not establish causal relationships.

Some of the original recommendations should therefore be interpreted as hypotheses rather than proven business effects.

### 6. No SQL / BI workflow

The original version mainly uses Python.

A stronger Data Analyst version would move the transaction analysis into SQL and present the main KPIs through a dashboard.

### 7. Dataset source/licensing documentation needs improvement

The license/copyright section of the original notebook should be re-verified because the copyright names shown there are not clearly connected to the dataset author identified elsewhere in the notebook.
